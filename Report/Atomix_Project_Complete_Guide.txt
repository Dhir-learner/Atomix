-------------------------------------------------------------------------------------
1. WHAT ATOMIX IS (ONE PARAGRAPH)
-------------------------------------------------------------------------------------
Atomix is a virtual chemistry laboratory built in Unity 6 (version 6000.3.7f1, Built-in
Render Pipeline). It runs in VR on Meta Quest / OpenXR headsets and, with no headset, on
a Windows PC using keyboard and mouse. A student picks one of 8 inorganic reactions from
an in-game Reaction Book, can first watch a molecular-level explanation (recorded video
or a live 3D ball-and-stick animation), then performs the experiment "free-hand" by
actually pouring liquids, adding solids and heating. The lab measures the amounts used,
judges the experiment (correct order? too much? too little? heated correctly?), explains
any mistake in chemistry terms, and lets the student ask an AI Lab Assistant (voice or
typed) that knows exactly what they just did - and still works offline. Every attempt is
saved to a history, successful ones get an accuracy score and 1-3 stars, scientific
graphs (energy profile, enthalpy, entropy, Gibbs energy) explain the reaction, and a
separate test scene gives randomized timed practical + theory tasks with a coin economy
and a downloadable HTML/CSV report.

Learning cycle:  Choose -> Learn -> Experiment -> Make mistakes -> Understand ->
                 Ask AI -> Review history -> Analyse graphs -> Try again

-------------------------------------------------------------------------------------
2. WHY IT EXISTS (PROBLEM)
-------------------------------------------------------------------------------------
* Real lab time is limited, reagents cost money, and dangerous reactions (sodium or
  potassium in water) cannot be practised freely by students.
* Students see the macroscopic change (fizzing, colour) but not the molecular cause.
* Existing virtual labs judge "did the right objects touch", not "how much, in what
  order, for how long", so they cannot explain realistic mistakes.
* AI chatbots answer generic questions but do not know the student's live experiment,
  and they stop working without internet.
* VR-only systems exclude students without headsets.
Atomix combines all the missing pieces in one app (see the report, Chapter 2).

5. HOW A NORMAL SESSION WORKS (USER JOURNEY)
-------------------------------------------------------------------------------------
1. Launch -> Main menu -> Practice.
2. First visit: an onboarding card explains the goal ("the AMOUNT is what is judged").
   A live objective line at the top always says what to do next.
3. Open the Reaction Book (B on desktop), flip pages (arrow keys) or press 1-8.
4. Choose difficulty: Guided (tolerance x1.5, targets shown), Standard (x1.0),
   Expert (x0.6, targets hidden; unlocked by passing Standard).
5. LEARN: watch the MP4 molecular video, or press 3D VIEW for the live animation.
   "ASK AI" asks the assistant about the exact step on screen.
6. PERFORM: only that reaction's apparatus is enabled. Grab a vessel, tilt to pour
   (pour rate depends on tilt angle), drop solids, light the Bunsen burner for heating.
   A floating tooltip + tracker shows live amounts (L toggles full/compact/off).
7. The engine decides: Success, or a failure with a chemistry-specific reason.
8. Success -> balanced equation, accuracy %, stars, sound/effects, graphs unlocked,
   molecular replay offered. Failure -> reason card; press Y to ask the AI why; F5 resets
   the bench and re-selects the same experiment.
9. Tab = experiment history, F = scientific graphs, P = periodic table, F1 = pause menu.

6. THE FREE-HAND REACTION ENGINE (the core algorithm)
-------------------------------------------------------------------------------------
File: VR/Assets/Scripts/FreeHandReactionEngine.cs (1,264 lines). Plain C# class; its only
Unity dependency is Time.deltaTime, so the same engine is used in the lab AND the test
scene, and it was tested outside Unity.

Per reagent i: target T_i, tolerance tau_i (%), live quantity q_i(t), difficulty scale s.
   q_min = T_i * (1 - s*tau_i/100)        q_max = T_i * (1 + s*tau_i/100)

Evaluated every frame:
 1. Not configured / already decided -> return stored state.
 2. ORDER: reagent added while an earlier one is missing -> FailWrongOrder.
 3. OVERDOSE: any q_i > q_max -> FailOverdose IMMEDIATELY (even mid-pour).
 4. Still pouring -> state Pouring, settle timer reset, InProgress.
 5. Not every reagent added yet -> state WaitingForInputs, InProgress.
 6. SETTLING: add frame time to settle timer; until 1.5 s -> InProgress.
    (So a student who pauses between reagents is never failed unfairly.)
 7. UNDERDOSE: any q_i < q_min -> FailUnderdose.
 8. PROCEDURE: heating time, and for CaCO3 the balloon must be fitted before heating
    ("CO2 escaped into the room") -> procedure failure.
 9. Otherwise SUCCESS -> score -> record attempt.

States: Idle -> WaitingForInputs -> Pouring <-> Settling -> Success / FailOverdose /
        FailUnderdose / FailWrongOrder / FailProcedure ; F5 resets to Idle.

-------------------------------------------------------------------------------------
7. SCORING (ExperimentScoring.cs)
-------------------------------------------------------------------------------------
   a_i = clamp(1 - |q_i - T_i| / (T_i * tau_i/100), 0, 1)     (1 = exactly on target)
   A   = 100 * min_i a_i                                       (worst reagent counts)
   Stars: fail = 0; A >= 60 -> 3; 25 <= A < 60 -> 2; else 1.
Why min, not average: one careful measurement must not hide a careless one, and a
fixed lump (the sodium block, always exact) must not inflate the score. Scoring always
uses the Standard tolerance so 3 stars mean the same precision on every level.
Example: reaction 2, H2SO4 target 20 ml, tau 8 % -> accepted 18.4-21.6 ml; 3 stars need
every reagent within +/-0.64 ml.

8. THE AI LAB ASSISTANT
-------------------------------------------------------------------------------------
Main files: InLabAssistantController.cs, ExperimentContextProvider.cs,
            ConvaiAssistantBackend.cs, ChemistryKnowledgeBase.cs, OfflineVoice.cs,
            LabTextInput.cs, LabAssistantCharacter.cs
Inputs : hold V = push-to-talk; Enter = type a question (no mic needed); Y = "why did my
         last experiment fail"; "Ask AI" buttons on graph and molecular panels; M minimises.
Context sent with every question: current reaction, quantities used, targets and ranges,
         verdict and failure reason, number of attempts and successes.
Path 1 (online): POST https://api.convai.com/character/getResponse -> reply text + voice.
Path 2 (offline, automatic on no credentials / no network / timeout / quota):
         ChemistryKnowledgeBase classifies the question by keyword scoring into an intent
         (WhyFailed, Quantities, Procedure, WhatHappened, Molecular, Graphs, Calculation,
         Safety, Progress; Overview if nothing matches) and answers from the game's own
         data, e.g. "you poured 27.4 ml where the equation needs 20.0, a 37% overdose".
         Spoken by the Windows speech synthesiser (Windows only; text elsewhere).
All Q&A is logged into the attempt history.
Note: the very first prototype used the Inworld AI SDK; it was replaced by the lighter
Convai REST integration. Leftover Inworld objects in LabAssistantScene may show
missing-script warnings; they are inert.
SECURITY: a real Convai API key was committed to Assets/Resources/LabAssistantSettings.asset
and is in git history -> ROTATE IT before sharing the repository.

9. MOLECULAR LEARNING
-------------------------------------------------------------------------------------
* Recorded videos: ReactionLearningController + ReactionLearningVideoCatalog (Unity
  VideoPlayer). 7 MP4 clips are in the project.
* Live 3D view (all 8 reactions): MolecularSceneCatalog (stages authored in code) +
  MolecularAnimationRenderer (renders to a RenderTexture).
  Red thinning bond = breaking, green thickening bond = forming, yellow dot = electron
  transfer. Only redox reactions (1, 4, 5, 8) show electron transfer; 2, 3, 6 show none.
  Atoms use CPK colours with element symbols; heating stages shake and warm the scene.

dH and dS come from standard thermodynamic data; Ea values are literature-plausible and
editable.

12. TESTING SCENE, COINS AND REPORTS
-------------------------------------------------------------------------------------
* 8 practical tasks + 10 theory MCQs = 18 task types (TheoreticalTasksManager has the
  questions, e.g. "What is the color of phenolphthalein in a basic solution?").
* Setup screen: choose 3, 5, 8, 10 or all tasks (clamped: theory-only 10, practical-only
  8, both 18). Timer waits until you choose.
* Practical tasks use the SAME free-hand engine, with targets hidden.
* Coins (AtomixCoinBank.cs, stored in PlayerPrefs, persistent):
    earn 5-100 per task by time left; bonuses: first clear +25, 3-streak +30,
    5-streak +60, perfect unaided run +50.
    spend: F2 hint 40 (procedure only, never the amount), F3 +30 s 60, F4 skip 100.
    ranks: Apprentice 0, Lab Technician 500, Chemist 1500, Senior Chemist 3500,
    Lab Master 7000 (lifetime coins).
* ExamSession records every task (passed, failed, skipped, timed out).
* Report card + "Download this test report": Atomix_Test_Report_<date>_<time>.html and
  .csv saved to Desktop (fallback Documents, then persistentDataPath). "Retake the test".

-------------------------------------------------------------------------------------
15. POLISH, COMFORT AND PRESENTATION
-------------------------------------------------------------------------------------
* All sounds synthesised at run time (AtomixAudio.cs) from one D-major palette; grab
  sounds pitched by object size; gentle failure tones (failure is normal in learning).
* Three audio buses under master volume; laboratory room tone OFF by default.
* Camera (CameraJuice.cs): shake on reactions; walking head-bob and sprint FOV kick are
  OFF by default (motion sickness).
* Post-processing (AtomixPostFx.cs): ambient occlusion, restrained bloom, antialiasing,
  box-projected reflection probe; no colour grading.
* Frame-rate-independent smoothing: x += (target - x) * (1 - exp(-k*dt)).
* Interactive 118-element periodic table, 13 achievements, pause/settings menu,
  async loading screen with tips, first-run onboarding.

18. HOW TO RUN / BUILD
-------------------------------------------------------------------------------------
1. Install Unity Hub + Unity 6000.3.7f1 (add Windows build support; add Android Build
   Support for Quest).
2. Open the folder "VR" (not the repo root) as the Unity project; let packages import.
3. Optional AI: put Convai credentials/character in Assets/Resources/LabAssistantSettings.asset.
   Without them the assistant uses the offline knowledge base.
4. Play in editor from MainMenuScene. No headset -> desktop mode starts automatically.
5. Windows build: File > Build Settings > PC, Mac & Linux Standalone > Build.
6. Quest build: switch platform to Android, enable OpenXR/Oculus, build and deploy.
More detail: README.md, START_HERE.md, ULTRA_DETAILED_SETUP_GUIDE.md, CONVAI_SETUP_GUIDE.md.

20. KNOWN LIMITATIONS
-------------------------------------------------------------------------------------
* Window title still says "UnityLab"/"AlinaInc" (legacy template name); renaming would
  reset saved coins/history/settings unless a migration is written.
* Cloud AI needs credentials + internet; offline answers only cover these 8 reactions.
* Offline voice is Windows-only.
* Re-selecting an experiment resets measurements but some visual substance may remain.
* Coins are per machine (PlayerPrefs) - no accounts/leaderboard.
* Floating glassware with no collider below stays floating.
* Committed API key must be rotated.
